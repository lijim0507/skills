## 归属规则

- 需求归 01，模块与公开接口归 02，函数与私有数据归 03，任务与证据归 04。
- 每份文档只有一个作者角色；实现者只填任务卡「验证 / 证据」栏、只勾状态。
- 同一事实只写一处：需求在 01，模块与公开接口在 02，函数与私有数据在 03，任务判据在 04。

## 交接规则

交接 = 产物 + 交接摘要 + 确认状态。

- **产物**：文件路径与版本。
- **交接摘要**：产物末尾的「交接给下一角色」，只写判断，不复述正文。
- **确认状态**：文档头 `状态：已确认`；未确认不交接。
- 下游只读产物与摘要，不读上游推理；发现缺口回交，不代改。

## 轻量模式

小项目可只保留 01 / 02 / 03 / 04；00 并入 README 的「项目契约」节。四份阶段文档都是必需：需求、架构、详细设计、执行记录不能互相替代；03 按模块拆成每模块一份，模块少的项目就是两三份小文件。轻量的是每份的内容深度，不是文件数。
