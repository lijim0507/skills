# 机器检查与人工检查

## 机器检查

```bash
python scripts/check_requirements.py    <SDD>/01-requirements.md
python scripts/check_architecture.py    <SDD>
python scripts/check_design.py          <SDD>
python scripts/check_implementation.py  <SDD>/04-implementation.md
python scripts/check_chain.py           <SDD>
python scripts/check_skill.py           <技能目录>
python scripts/check_loadsets.py        <技能目录>
```

## 输出怎么读

- 「结构检查通过 · 语义未验证」= 只证明章节、编号、链条、字段齐全
- 不覆盖：需求可验收性、架构可行性、设计可实现性、任务可执行性、模板语义、角色边界
- 脚本绿 ≠ 可以开工；开工由人启动
- 装载集在预算内只证明读的文件没超预算，不证明读得对、读得全

## 人工检查（确认前）

- **01**：3.1.1 清单与 3.3 需求卡编号一致；每条 SSR 有需求类别与来源；3.2 交互框图写明输入来源与输出消费方；验证准则可观察、可验证；4.1 / 4.2 追溯覆盖全部 SSR；未决项标清是否阻塞
- **02**：每条 SSR 有落点组件；5.3.4 / 5.3.5 / 5.3.6 三层都有组件定义（没有该层写“无”）；每个组件有「覆盖需求」；5.3.3 依赖矩阵与组件定义一致、依赖无环；5.4 只有一张产品整体行为图（参与者是产品实际阶段，如开机 / 工作 / 关机，不是组件调用），5.4.x 各阶段小节标题与表里的运行模式名跟图中参与者一一对应、顺序与迁移一致，每阶段表列齐全：运行模式 / 进入条件 / 进入动作 / 运行动作 / 退出条件 / 退出动作 / 异常处理；5.5 资源、5.6 调度、5.7 异常、5.8 假设有内容
- **03**：02 每个组件有一份 `03-design-<组件>.md`；8.2 每个软件单元有 8.2.2 函数设计（函数 ID、参数、返回值、全局 / 静态变量、程序流程图），与 7.1 组件分解一致；7.2.2 函数列表、7.2.3 函数关系、7.2.4 源代码文件清单齐全；每个公开接口有对应函数；9 可追溯性覆盖 SSR ↔ 详设；10 附录含数据质量与交接给实现
- **04**：每条软件需求 ID（`SSR…`）/ 异常（`R-xx`）/ 流程任务都有覆盖；任务卡自足；没有 `blocked` 未解

## 交接检查

- 下游接手所需的信息写在产物末尾或文档头；没有单独交接章时不强求
- 文档头状态为 `已确认`
- 下游没有替上游改正文；发现缺口有回交记录

## 写之前问四句

1. 我写了不属于我的文档吗？
2. 我做了不属于我的决定吗？
3. 我读了不该读的内容吗？
4. 我把上游缺口在下游私了吗？

任何一句“是”，停，按角色卡的退回规则处理。

## 模板符合度

脚本不检查模板符合度。确认前人工对照 `templates/` 检查：

- 章节顺序是否与模板一致
- 必填字段是否齐全
- 版本 / 状态是否写在文档头

## 回归

改技能后跑 `examples/todo-cli` 五道检查（requirements / architecture / design / implementation / chain，必须全通过）+ `check_skill.py` + `check_loadsets.py`。语义探针尚未实现，回归不包含该项；新增探针时必须能对空话规格报失败。
