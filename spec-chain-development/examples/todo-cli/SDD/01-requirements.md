## 1 概述

### 1.1 目的

定义 Todo CLI 的软件需求：用户可以新增待办任务、列出全部任务。本文是架构与详细设计的输入。

### 1.2 适用范围

覆盖 Todo CLI v1 的命令行功能；不覆盖多用户、同步、图形界面。

| 术语 / 缩略语 | 含义 |
| --- | --- |
| REQ | 软件需求（Software Requirement） |
| CLI | 命令行界面 |
| Todo | 一条待办任务记录 |

## 2 软件需求

### 2.1 简介

**需求清单**

| 软件需求 ID | 名称 | 优先级 | 来源 |
| --- | --- | --- | --- |
| REQ-TC-ADD-001 | 新增任务 | P0 | 用户需求（N1） |
| REQ-TC-LIST-001 | 列出任务 | P0 | 用户需求（N1） |

**需求间依赖关系**

| 需求 | 依赖 | 说明 |
| --- | --- | --- |
| REQ-TC-ADD-001 | 无 | 独立可交付 |
| REQ-TC-LIST-001 | REQ-TC-ADD-001 | 列出的前提是有任务 |

**输入与输出**

| 输入 | 来源 | 输出 | 消费方 |
| --- | --- | --- | --- |
| `add <标题>` 命令与标题参数 | 用户 | 成功 / 错误提示 | 用户 |
| `list` 命令 | 用户 | 任务列表文本 | 用户、脚本 |

### 2.2 软件需求

#### 2.2.1 任务管理

**[REQ-TC-ADD-001] 新增任务**

**需求 ID**：REQ-TC-ADD-001 ｜ 优先级：P0 ｜ 来源：用户需求（N1）

**描述**

用户可以通过命令行新增一条待办任务。

**验证准则**

- 应接受任务标题参数，创建后出现在任务列表中。
- 标题为空的输入不得创建任务，应返回错误提示。
- 新增成功后应返回成功提示。

**依赖**

- 无。

**[REQ-TC-LIST-001] 列出任务**

**需求 ID**：REQ-TC-LIST-001 ｜ 优先级：P0 ｜ 来源：用户需求（N1）

**描述**

用户可以查看当前所有待办任务。

**验证准则**

- 应列出全部任务，每条带编号与完成状态。
- 没有任务时应返回空列表提示。
- 输出顺序应与添加顺序一致。

**依赖**

- REQ-TC-ADD-001：没有任务时列表为空，但命令仍可用。
