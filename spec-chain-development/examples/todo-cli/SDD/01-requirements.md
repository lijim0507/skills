## 1 概述

### 1.1 目的

定义 Todo CLI 的软件需求：用户可以新增待办任务、列出全部任务。本文是架构与详细设计的输入。

### 1.2 适用范围

覆盖 Todo CLI v1 的命令行功能；不覆盖多用户、同步、图形界面。

### 1.3 术语和缩略语

| 术语 / 缩略语 | 含义 |
| --- | --- |
| REQ | 软件需求（Software Requirement） |
| CLI | 命令行界面 |
| Todo | 一条待办任务记录 |

## 2 软件需求

### 2.1 软件需求简介

#### 2.1.1 软件需求清单

| 需求编号 | 软件需求描述 | 需求类别 | 来源 | 备注 |
| --- | --- | --- | --- | --- |
| REQ-TC-ADD-001 | 新增一条待办任务 | 功能性 | 用户需求（N1） | — |
| REQ-TC-LIST-001 | 列出全部待办任务 | 功能性 | 用户需求（N1） | — |

#### 2.1.2 软件需求之间的依赖关系

| 需求 | 依赖的需求 | 说明 |
| --- | --- | --- |
| REQ-TC-ADD-001 | 无 | 独立可交付 |
| REQ-TC-LIST-001 | REQ-TC-ADD-001 | 列出的前提是有任务 |

#### 2.1.3 输入与输出

| 输入 | 来源 | 输出 | 消费方 |
| --- | --- | --- | --- |
| `add <标题>` 命令与标题参数 | 用户 | 成功 / 错误提示 | 用户 |
| `list` 命令 | 用户 | 任务列表文本 | 用户、脚本 |

### 2.2 交互框图

用户通过命令行与 Todo CLI 交互：`add` 写入任务，`list` 读出任务；任务持久化在本地文件。

```mermaid
flowchart LR
  User[用户] -->|add / list| CLI[Todo CLI]
  CLI -->|读写| Store[(本地任务文件)]
```

### 2.3 软件需求

#### 2.3.1 任务管理

**[REQ-TC-ADD-001] 新增任务**

**需求编号**：REQ-TC-ADD-001 ｜ **需求类别**：功能性 ｜ **来源**：用户需求（N1）

**描述**：用户可以通过命令行新增一条待办任务。

**验证准则**：

- 应接受任务标题参数，创建后出现在任务列表中。
- 标题为空的输入不得创建任务，应返回错误提示。
- 新增成功后应返回成功提示。

**依赖**：无

**[REQ-TC-LIST-001] 列出任务**

**需求编号**：REQ-TC-LIST-001 ｜ **需求类别**：功能性 ｜ **来源**：用户需求（N1）

**描述**：用户可以查看当前所有待办任务。

**验证准则**：

- 应列出全部任务，每条带编号与完成状态。
- 没有任务时应返回空列表提示。
- 输出顺序应与添加顺序一致。

**依赖**：REQ-TC-ADD-001（没有任务时列表为空，但命令仍可用）
