# 2 概述

## 2.1 目的

定义 Todo CLI 的软件需求：用户可以新增待办任务、列出全部任务。本文是软件架构设计的输入。

## 2.2 适用范围

覆盖 Todo CLI v1 的命令行功能；不覆盖多用户、同步、图形界面。

## 2.3 术语和缩略语

| 术语/缩略语 | 解释 |
| ----------- | ---- |
| SSR | 软件需求（Software Safety/Software Requirement），本文的需求编号前缀 |
| CLI | 命令行界面 |
| Todo | 一条待办任务记录 |
| TSR | 系统需求，本文的需求来源 |

# 3 软件需求

## 3.1 软件需求简介

### 3.1.1 软件需求清单

| 软件需求ID | 软件需求 描述 | 备注 |
| ---------- | ------------- | ---- |
| SSR001     | 新增一条待办任务 | 功能性 |
| SSR002     | 列出全部待办任务 | 功能性 |

### 3.1.2 软件需求之间的依赖关系(适用于含功能安全的需求点)

|        | SSR001 | SSR002 |
| ------ | ------ | ------ |
| SSR001 |        | ●      |
| SSR002 | ●      |        |

SSR002 依赖 SSR001：列表展示的任务由新增命令写入。

## 3.2 交互框图

用户通过命令行与 Todo CLI 交互：`add <标题>` 写入任务、`list` 读出任务。输入为两条命令及标题参数，来源是用户；输出为成功 / 错误提示与任务列表文本，消费方是用户与脚本。任务持久化在本地 JSON 文件。

```mermaid
flowchart LR
  User[用户] -->|add / list| CLI[Todo CLI]
  CLI -->|读写| Store[(本地任务文件)]
```

## 3.3 软件需求

### 3.3.1 新增任务

| 需求 ID   | SSR001 |
| --------- | ------ |
| 需求描述  | 用户可以通过命令行新增一条待办任务：接受任务标题参数，创建一个未完成的 Todo 记录，成功后给出成功提示，并把任务持久化到本地文件。 |
| 需求类别  | 功能性 |
| 目标阶段  | 运行 |
| ASIL等级  | 不适用（非安全相关） |
| 优先级    | 高 |
| 复杂度    | 低 |
| 来源于    | TSR001[不适用]（N1 新增待办） |

| 需求分析  | 可验证性：可验证。 |
| 需求分析  | 成本进度分析：一人日。 |
| 需求分析  | 运行环境分析：Python 3 标准库，单进程。 |
