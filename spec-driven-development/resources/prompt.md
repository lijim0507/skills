# 变更规格模板

将以下模板复制到 `specs/<变更名>/spec.md` 并填写：

```markdown
# 变更规格：<变更名>

## 背景
为什么需要这次变更，现状是什么。

## 目标
变更完成后要达成的可验证结果。

## 范围
本次要改动的模块、文件或接口清单。

## 非目标
明确不做的事情，防止范围蔓延。

## 影响面
可能受影响的调用方、配置、文档与测试。

## 验收标准
- 条目 1：可观察、可核对的结果
- 条目 2：……
```

写作要求：

- 每条验收标准必须可观察、可核对，避免"更好用"这类模糊表述
- 范围写到文件或接口级别，便于拆解任务
- 先写非目标再写细节，主动收缩范围
