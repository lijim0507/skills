# 02-plan-research.md —— Phase 0 技术调研与决策

> 角色：技术总监 ｜ 依据：02-plan.md ｜ 版本：r1 ｜ 状态：已确认

## D-00 模块划分

- **问题**：按什么边界划分模块？
- **结论**：CommandParser / TaskStore / TaskRenderer。
- **依据**：解析、持久化、呈现的变更原因不同；TaskStore 独占写权限。
- **状态**：采纳
- **验证方式**：依赖检查 + 单元测试
- **被否决的方案**：
  - 单文件脚本——否决原因：难测试，职责混在一起。
  - 按 UI / Service / Repository 分层——否决原因：对本项目是空壳分类，不是具体模块。

## D-01 存储

- **问题**：JSON 文件还是 SQLite？
- **结论**：JSON 文件。
- **依据**：单用户、离线、可读性优先。
- **状态**：采纳
- **验证方式**：读写测试 + 故障注入
- **被否决的方案**：
  - SQLite——否决原因：对单用户过重，增加依赖。

## D-02 写入

- **问题**：直接覆写还是临时文件 + 原子替换？
- **结论**：临时文件 + 原子替换。
- **依据**：契约 C-02，失败不破坏原文件。
- **状态**：采纳
- **验证方式**：模拟写入失败，原文件仍可读
- **被否决的方案**：
  - 直接覆写——否决原因：失败会破坏原文件。
