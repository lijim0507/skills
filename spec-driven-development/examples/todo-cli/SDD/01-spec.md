# 01-spec.md —— Todo CLI 需求规格

> 角色：产品经理 ｜ 依据：示例需求 ｜ 版本：r3 ｜ 状态：已确认

## 产品定位

一句话：为在终端工作的开发者，在刚想到待办时，解决切换应用太慢的问题，带来 3 秒内记录的价值。

| ID | 类型 | 消费者 | 场景 | 问题 | 价值 |
| --- | --- | --- | --- | --- | --- |
| P1 | 主要 | 开发者 | 在终端里刚想到一件事 | 记待办要切换应用或打开浏览器 | 3 秒内记下一条待办 |
| P2 | 主要 | 开发者 | 在终端里想确认今天要做什么 | 查看待办要切换应用 | 在终端里按顺序看到待办 |
| N1 | 不服务 | 图形界面用户 | 不使用终端 | — | — |

**成功信号**：在目标机器上连续添加 100 条待办，list 顺序正确率 100%；测量方式为脚本比对输出顺序。

## 范围外

- 图形界面：本轮不做。
- 提醒 / 推送 / 云同步：本轮不做。
- 多用户协作：本轮不做。

## 用户故事

### US1 记录待办

**定位**：P1

**消费者 / 场景**：开发者在终端里刚想到一件事。

**想要**：立刻记下，不切换应用。

**结果**：待办写入本地列表，命令返回成功。

**对应功能**：FR-001

### US2 查看待办

**定位**：P2

**消费者 / 场景**：开发者在终端里想确认今天要做什么。

**想要**：按顺序看到待办。

**结果**：终端按创建顺序输出待办。

**对应功能**：FR-002

## 功能需求

- **FR-001** 添加待办
  - **来源**：US1
  - **优先级**：必须
  - **依据**：3 位终端开发者访谈都提到“切换应用打断思路”；现有工具没有终端入口。
  - **行为**：接收一条待办文本，追加到本地列表。
  - **输入 / 输出**：`todo add <text>`；成功退出码 0，失败非 0 且 stderr 有错误。
  - **规则与边界**：文本为空时拒绝；数据文件损坏时返回错误，不覆盖原文件。
  - **验收**：
    - Given 空列表，When 运行 `todo add "买牛奶"`，Then 退出码为 0，且 `todo list` 输出包含“买牛奶”。
    - Given 数据文件损坏，When 运行 `todo add "买牛奶"`，Then 退出码非 0，且原文件内容不变。
  - **外部契约**：EC-01、EC-02

- **FR-002** 查看待办
  - **来源**：US2
  - **优先级**：必须
  - **依据**：同一批访谈中，开发者希望在终端里直接确认顺序，不想打开浏览器。
  - **行为**：按创建顺序列出待办。
  - **输入 / 输出**：`todo list`；stdout 每行一条；空列表输出 “No todos”，退出码 0。
  - **规则与边界**：数据文件损坏时返回错误；空列表不报错。
  - **验收**：
    - Given 有两条待办，When 运行 `todo list`，Then 按创建顺序输出两行。
    - Given 空列表，When 运行 `todo list`，Then 输出 “No todos”，退出码 0。
  - **外部契约**：EC-02

## 外部契约

| ID | 消费者 | 契约内容 | 版本 / 兼容 | 验证方式 | 关联 FR |
| --- | --- | --- | --- | --- | --- |
| EC-01 | 开发者 / 脚本 | `todo add <text>` / `todo list` 命令；成功退出码 0，失败非 0 | v1；命令名不变 | CLI 冒烟 + 退出码断言 | FR-001、FR-002 |
| EC-02 | 开发者 / 脚本 | stdout 每行一条；空列表输出 “No todos”；错误写 stderr | v1；输出格式不变 | stdout 快照 | FR-001、FR-002 |

## 交接给技术总监

- 产品定位：P1 开发者在终端记录；P2 开发者在终端查看
- 必须兑现的外部契约：EC-01 CLI 命令、EC-02 CLI 输出
- 不可妥协的约束：离线、Python 3.10+、单进程
- 验收方式：在目标机器上跑命令并检查输出
- 明确不做：图形界面、提醒/推送/云同步、多用户协作
- 需要技术判断的取舍：存储格式与并发写入策略
