# 02-plan.md —— Todo CLI 技术方案

> 角色：技术总监 ｜ 依据：01-spec.md r3 ｜ 版本：r1 ｜ 状态：已放行

## 方案总览

单进程 Python CLI，CommandParser 解析参数，TaskStore 负责 JSON 文件读写，TaskRenderer 负责输出。写入使用临时文件 + 原子替换，保证失败不破坏原文件。

## 技术上下文

| 项 | 内容 |
| --- | --- |
| 运行平台 / 运行时 | Python 3.10+ |
| 工具链 | 标准库、pytest |
| 相关既有模块 | 无 |
| 关键约束 | 离线、单进程、单文件数据 |

## 模块划分

| 模块 | 职责 | 拥有或读写的数据 | 依赖 | 写权限 | 变更原因 |
| --- | --- | --- | --- | --- | --- |
| CommandParser | 解析命令与参数，分发到 TaskStore / TaskRenderer | 无 | TaskStore、TaskRenderer | 无 | CLI 命令形状变化 |
| TaskStore | 读写待办 JSON 文件 | todos.json | 无 | 唯一写权限 | 存储格式或可靠性要求变化 |
| TaskRenderer | 格式化列表输出 | 无 | TaskStore | 无 | 输出格式变化 |

## 数据与契约

- 数据模型：todos.json 是对象数组，字段 id / text / created_at；详见 `02-plan-data-model.md`
- 内部契约：CommandParser / TaskStore / TaskRenderer 的公开接口，详见 `02-plan-contracts.md`
- 外部契约：EC-01 / EC-02 见 `01-spec.md`

## 交接给任务拆解

- 方案一句话：单进程 Python CLI，JSON 文件存储，原子替换
- 模块与边界：CommandParser / TaskStore / TaskRenderer；TaskStore 独占写权限
- 技术依赖与解锁关系：先有 TaskStore，CommandParser 和 TaskRenderer 才能接；批次由 03 定
- 每条 FR 的落点模块：FR-001 → CommandParser + TaskStore；FR-002 → TaskStore + TaskRenderer；EC-01/EC-02 → CommandParser + TaskRenderer
- 验证环境与命令：pytest；Python 3.10+
- 主要风险与回滚：并发写坏文件，使用文件锁；失败保留原文件
- 需要产品确认的取舍：单进程 + 文件锁；无服务端监控
