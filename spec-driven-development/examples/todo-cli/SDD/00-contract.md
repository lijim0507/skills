# 00-contract.md —— Todo CLI 项目契约

> 作者：人（AI 起草） ｜ 版本：r1 ｜ 状态：已确认
> 本项目所有改动都要遵守的规则和边界，不是某一次需求。

## 原则

### C-01 离线可用

所有功能在无网络环境下可用。

- **可判定**：断网后跑完整 CLI 冒烟，全部通过
- **出处**：用户访谈：终端开发者常在无网或受限网络环境工作

### C-02 失败不破坏数据

任何写操作失败都不能破坏已有待办。

- **可判定**：故障注入使写入失败，原 todos.json 仍可读且内容不变
- **出处**：事故复盘：早期版本直接覆写导致数据丢失

### C-03 单进程

本轮只支持单进程使用，不做多进程并发保证。

- **可判定**：文档与测试只覆盖单进程
- **出处**：范围决策，2026-10-19

## 边界

| ID | 边界 | 允许 | 禁止 | 判定方式 |
| --- | --- | --- | --- | --- |
| B-01 | 代码目录 | `src/todo/`、`tests/` | 仓库根目录新增脚本 | 目录清单检查 |
| B-02 | 依赖 | Python 3.10+ 标准库、pytest | 引入运行时第三方依赖 | 依赖清单检查 |

## 技术约束

- 平台 / 运行时：Python 3.10+
- 依赖政策：运行时只用标准库；开发期可用 pytest
- 数据 / 安全 / 合规：本地文件，无服务端，不上传
- 兼容性：命令形状与输出格式在 v1 内保持稳定

## 原则冲突

- C-01 与 B-02 冲突时以 C-01 为准：为离线可用可以引入标准库外的本地依赖，但必须由人批准。

## 治理

- 修订需记：版本号 / 批准日期 / 修订理由
- 本契约优先于其他习惯做法
- 违反本契约的方案，必须在 `02-plan.md` 的「契约合规」节说明为什么值得破例；**破例由人批准并记录日期**
- 破例只对本次方案有效，不自动成为新原则
