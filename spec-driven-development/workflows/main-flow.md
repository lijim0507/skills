# SDD 主流程

本文件是流程权威。角色卡定义谁有权做什么，模板定义产物长什么样，交接定义怎么交给下一角色。

## 治理

`00-contract.md` 在项目初始化时由人写一次，项目级生效，不占迭代。后续每次迭代默认遵守，不重复确认。

## 一次迭代

| 步骤 | 角色 | 产出 | 结束 |
| --- | --- | --- | --- |
| 01 | 01 产品经理 | `01-spec.md` | 写完即结束 |
| 02 | 02 技术总监 | `02-plan*.md` | 写完即结束 |
| 03 | 03 任务负责人 | `03-tasks.md` | 写完即结束 |
| 执行 | 执行者 | 代码 + 03 证据 | 人按 01 验收 |

## 开工

用户选角色，AI 读角色卡和目标模板，写调用头。调用头写不全就停。

```text
本次角色：<01 / 02 / 03 / 执行>
本次阶段：<01 / 02 / 03 / 执行>
只读：<上游产物 + 角色卡 + 模板>
只写：<本阶段允许写的文件>
交接：<交给谁、看哪一节>
```

一个执行单元只做一个阶段。写完即结束，不主动进入下一角色；下一个角色由人启动。

## 交接

上游把一个阶段交给下游，交三样：

- **产物**：文件路径与版本。
- **交接摘要**：产物末尾的「交接给下一角色」，只写 diff 里看不出来的判断。
- **确认状态**：文档头 `状态：已确认`；未确认的产物不交接。

下游先读产物和交接摘要，不读上游的推理过程；读不出要做什么，回交。

## 回交

下游发现问题，不自己改上游，提交问题包：

- **问题**：哪条 FR / 模块 / 任务卡对不上。
- **证据**：文件、行、复现方式。
- **影响**：阻塞哪条任务、哪条验收。
- **可选方案**：各自的代价。
- **需要谁决策**：01 / 02 / 03。

上游决策：改正文 / 拒绝 / 有条件接受。改正文要记修订记录、重新确认；不改正文却让下游硬做，下游标 `blocked`。

## 回退与变更

- 需求矛盾回 01，方案缺口回 02，任务不清回 03。
- 回退由原决策角色重新评估，不由下游代改。
- 正文一改，确认状态回到 `待确认`；下游已完成的产物要重新检查。

## 变更类型

| 类型 | 入口 |
| --- | --- |
| 新功能 | 01 |
| 行为变更 / 修缺陷 / 契约变更 | 01 |
| 重构 | 02 |
| 文案 / 小改 | 不走 |

判不准按上游处理。

## 完成判据

03 无 `[ ]` 残留（`[~]` 作废不算）；每条 FR 在目标环境跑过，证据在 03 任务卡；人按 01 验收。
