# SDD v3 主流程

本文件是流程权威。角色卡定义谁来做，模板定义做成什么样，门定义什么时候停。

## 开工前：角色选择与调用头

用户只选角色；必要时再说阶段。AI 根据角色卡写出调用头，作为开工回执；用户确认或纠正。

每次只启用一个角色。AI 写：

```text
本次角色：<00-06 + 名称>
本次阶段：<S0-S9>
只读：<上游产物 + 角色卡 + 模板>
只写：<本阶段允许写的文件>
停点：<门 / 评审 / 任务完成>
禁止：<不能写什么、不能做什么>
```

写不完整就停，问一句比猜一次便宜。

## 角色切换

- 换角色 = 换上下文：只读上游产物，不读上一角色的推理过程。
- 同一会话无法隔离时，用新会话或新 sub-agent；至少要在角色调用头里声明“只读上游产物”。
- 切换后先复述三句：拿到了什么、要做什么、还缺什么。复述不出来就退回。

## 变更类型入口

不是所有改动都走 S0–S9。按 `references/routes.md` 选入口：

| 类型 | 起点 | 说明 |
| --- | --- | --- |
| 新功能 | S0 | 完整流程 |
| 行为变更 | S1 | 01 必走；00/02 子件可轻量 |
| 修缺陷 | S1 | 01 写清“错在哪”，02 写根因，03 只拆修复 |
| 重构 | S3 | 外部行为不变时，01 可省；02 必须写“行为不变”的证据 |
| 契约变更 | S1 | 外部契约先回 01，再走 02/03 |
| 小改 / 文案 | 不走 SDD | 不改外部可观察行为 |

## 门简报

每个门先给一页简报，再放完整清单。简报只写四块：

- **要你拍板的决定**：3–5 条，按影响排序
- **代价 / 风险**：工期、成本、运行开销、不可逆点
- **未决项**：是否阻塞，阻塞谁
- **建议**：approve / reject / 退回哪一层

完整清单是附录，不要求裁决人逐条勾。签字格式：

```text
approve ｜ 裁决人：<名字> ｜ 日期：YYYY-MM-DD ｜ 版本：rN
```

## 四个交接动作

- **接手先复述**：02/03/04 动笔前写三句：拿到了什么、据此要做什么、还缺什么。
- **退回就改上游**：不可行、方案缺口、需求矛盾，回上游改正文，不在下游降级。
- **评审要隔离**：评审者只拿产物和清单，产出“查了哪些项、发现几条、每条在哪”。
- **改动即作废**：门签字带正文版本；正文一改，结论回到待审。

## 角色边界检查

每个门、每次交接回答四句：

1. 我写了不属于我的文档吗？
2. 我做了不属于我的决定吗？
3. 我读了不该读的内容吗？
4. 我把上游缺口在下游私了吗？

任何一句“是”，先停，按角色卡退回规则处理。

## 轻量模式

小项目可以只保留 01 / 02 / 03；00 并入 README 的“项目宪法”节；04 只写验收记录；02 子件并入 02-plan 对应节。

轻量的是文档量，不是判断量：门不能省，角色边界不能省，签字不能代签。

## 不确定就标

需求不确定标 `[NEEDS CLARIFICATION]`，不猜着写；执行不确定标 `blocked`，写明卡在哪、等谁。没定的不进正文，定了再改，改了就重签。

## 完成判据

03 无 `[ ]` 残留（`[~]` 作废不算）；验收按 01 的场景在真实环境跑过并由人签字。

## 落点

动了哪份文档、从哪重走、缺件回哪一层，见 `references/resume.md` 的落点表。
