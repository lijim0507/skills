# SDD 主流程

本文件是流程权威。角色卡定义谁来做，模板定义做成什么样，交接定义什么时候停。

## 一次迭代

| 步骤 | 角色 | 做什么 | 结束 |
| --- | --- | --- | --- |
| S0 | 人（AI 起草） | 写 `00-contract.md`：项目长期规则与边界 | 人确认 |
| S1 | 01 产品经理 | 写 01：定位、范围外、US、FR、外部契约、未决项 | 停，人放行 |
| S2 | 02 技术总监 | 写 02：模块、数据、契约、决策、质量、风险、验证 | 停，人放行 |
| S3 | 03 任务负责人 | 写 03：批次、任务卡、覆盖映射 | 停，人放行 |
| S4 | 执行者 | 按任务卡实现，填证据，勾状态 | 人按 01 验收 |

## 开工

用户选角色，AI 读角色卡和目标模板，写调用头。调用头写不全就停。

```text
本次角色：<01 / 02 / 03 / 执行>
本次阶段：<S0-S4>
只读：<上游产物 + 角色卡 + 模板>
只写：<本阶段允许写的文件>
交接：<交给谁、看哪一节>
```

## 放行

每个执行单元结束，AI 停，给三行：

- 改了什么：<产物路径与要点>
- 要你定什么：<1-3 条，按影响排序>
- 建议：继续 / 退回 <哪一层>

人回“继续”才起下一个执行单元。不回、回“你看着办”，按未放行处理。

## 退回

- 下游发现上游缺口：回上游改正文，不在下游降级、不私了。
- 需求矛盾回 01，方案缺口回 02，任务不清回 03。
- 改正文后，下游已完成的产物要重新检查；放行不跨版本继承。

## 变更类型

| 类型 | 入口 |
| --- | --- |
| 新功能 | S0 |
| 行为变更 / 修缺陷 / 契约变更 | S1 |
| 重构 | S2 |
| 文案 / 小改 | 不走 |

判不准按上游处理。

## 完成判据

03 无 `[ ]` 残留（`[~]` 作废不算）；每条 FR 在目标环境跑过，证据在 03 任务卡；人按 01 验收。
