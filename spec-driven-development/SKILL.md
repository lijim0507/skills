# 规范驱动开发（v3 角色卡版）

## 这是什么

一个**受流程和文档约束的角色扮演包**：一个包，七张角色卡，一套共享的流程、文档和检查标准。每次使用先选角色；角色决定视角与权限，流程和文档决定边界与产物。

不是三个独立 skill。拆开会丢掉角色之间的交接契约：01 的哪条 FR 要被 02 兑现、02 的哪个模块要被 03 覆盖、03 的哪张卡要被 04 验收。

## 四层模型

| 层 | 作用 | 看哪里 |
| --- | --- | --- |
| 流程 | 什么时候做什么、到哪停、退回哪 | `workflows/main-flow.md` |
| 文档 | 每份文件写什么、长什么样、怎么追溯 | `references/doc-set.md`、`templates/` |
| 角色 | 谁决定、谁读写、谁签字 | `references/role-map.md`、`roles/` |
| 检查 | 结构 lint、评审记录、角色边界 | `references/checks.md`、`references/gates.md` |

角色是入口，流程和文档是护栏。换角色不等于换标准。

## 每次开工先写角色调用头

```text
本次角色：01 产品经理
本次阶段：S1
只读：需求 + roles/01-pm.md + templates/01-spec.md
只写：SDD/01-spec.md
停点：门 1
禁止：02 / 03 / 代码
```

写不完整就停，不要凭印象开工。

## 变更类型路由

不是所有改动都走 S0–S9。完整分流见 `references/routes.md`。

| 类型 | 起点 | 通常可省 |
| --- | --- | --- |
| 新功能 | S0 | 无 |
| 行为变更 | S1 | 00、02 子件可轻量 |
| 修缺陷 | S1 | 00、02 子件、部分门简报 |
| 重构 | S3 | 01（外部行为不变时） |
| 契约变更 | S1 | 00、02 子件按需 |
| 文案 / 不改外部行为的小改 | 不走 SDD | 全部 |

## 术语

| 词 | 含义（拥有者） |
| --- | --- |
| 规格 | 可观察行为：谁、什么场景、什么结果；不写步骤（01） |
| 方案 | 构造决策：模块、依赖、数据、顺序、失败处理（02） |
| 任务卡 | 一次可交付的工作单元及其判据（03） |
| 契约 | 跨边界的稳定接口：外部在 01，内部在 02 |
| 证据 | 证明任务卡完成的可复核输出（03/04） |
| 门 | 人裁决的停机点（裁决人） |
| 角色卡 | 职能、权限、输入输出、停点、退回规则的合同（本 skill） |
| 待审 | 未签字，或签字已随正文改动作废（裁决人） |
| 阻塞 | 上游未定，禁止下游继续（上游角色） |
| 收敛 | 缺口的处置结论；只追加任务，不改正文（验收人） |

## 执行纪律

- **先声明角色，再动笔**。角色调用头写不出来，就退回，不猜。
- **换角色就换上下文**。只读上游产物，不读上一角色的推理过程；同一会话无法隔离时，用新会话或新 sub-agent。
- **角色边界检查**。每个门回答四句：我写了不属于我的文档吗？我做了不属于我的决定吗？我读了不该读的内容吗？我把上游缺口在下游私了吗？
- **到门即停**。未批准不得开工；“你看着办”仍按待审处理。
- **回上游改正文**。不可行、方案缺口、需求矛盾，回上游改正文，不在下游降级。
- **评审隔离**。评审者只拿产物和清单，不参加写作；产出“查了哪些项、发现几条、每条在哪”。“未发现问题”不算结论。
- **签字绑定版本**。正文一改，结论回到待审，由人重签。
- **lint 只证结构**。脚本绿不等于门通过。

## 断点与维护

新会话只凭 `SDD/` 文件恢复，不靠聊天记忆。前置检查、落点表、“缺件回哪一层”见 `references/resume.md`。

- 入口 ≤ 8 KB；角色卡 ≤ 3 KB；reference ≤ 5 KB；流程 ≤ 5 KB。
- 改模板或脚本后：跑 `examples/todo-cli` 四道检查 + `scripts/check_skill.py` + `scripts/check_loadsets.py .`。
