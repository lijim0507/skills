# 规范驱动开发

## 这是什么

一个受流程和文档约束的角色扮演包：四张角色卡、五份文档、一条五步流程。角色决定视角和写权限，流程决定顺序和交接触发，文档决定产物。

不是四个独立 skill。拆开会丢掉交接契约：01 的哪条 FR 要被 02 兑现、02 的哪个模块要被 03 覆盖、03 的哪张卡要被执行者完成。

## 五步

流程权威见 `workflows/main-flow.md`。

| 步骤 | 执行单元      | 产出               | 结束         |
| ---- | ------------- | ------------------ | ------------ |
| S0   | 人（AI 起草） | `00-contract.md` | 人确认       |
| S1   | 01 产品经理   | `01-spec.md`     | 停，人放行   |
| S2   | 02 技术总监   | `02-plan*.md`    | 停，人放行   |
| S3   | 03 任务负责人 | `03-tasks.md`    | 停，人放行   |
| S4   | 执行者        | 代码 + 03 证据     | 人按 01 验收 |

## 四张角色卡

| 卡                          | 角色       | 输入                         | 输出               | 交给   |
| --------------------------- | ---------- | ---------------------------- | ------------------ | ------ |
| `roles/01-pm.md`          | 产品经理   | 需求 + 01 模板          | `01-spec.md`     | 02     |
| `roles/02-architect.md`   | 技术总监   | 00 + 01 + 代码事实 + 02 模板 | `02-plan*.md`    | 03     |
| `roles/03-owner.md`       | 任务负责人 | 00 + 01 + 02 + 03 模板       | `03-tasks.md`    | 执行者 |
| `roles/04-implementer.md` | 执行者     | 03 任务卡 + 代码             | 代码 + 证据 + 勾选 | 人验收 |

角色由人挑选，AI 不自己切换角色。

## 角色调用头

每次开工先写回执，作为本次执行单元的边界：

```text
本次角色：<01 / 02 / 03 / 执行>
本次阶段：<S0-S4>
只读：<具体文件清单>
只写：<具体文件清单>
交接：<交给谁、看哪一节>
```

写不出来就停，问一句比猜一次便宜。

## 执行纪律

- **一次只启用一个角色**。写之前先声明角色；声明不了就退回。
- **换角色就换执行单元**。新会话或新 sub-agent，只给上游产物、角色卡和模板；不给上一角色的推理过程。
- **到交接点即停**。写完用三行摘要（改了什么 / 要你定什么 / 建议继续还是退回）请人放行；未放行不进入下一阶段。
- **回上游改正文**。下游发现上游缺口，回上游改正文，不在下游降级、不私了。
- **单一事实源**。外部契约在 01，内部契约在 02，任务判据在 03；下游引用编号，不复制正文。
- **00 独立于需求**。00 是项目总体约束，所有阶段默认遵守；不在 01 里逐条引用或做冲突裁决。
- **执行者只对任务卡负责**。只写代码、测试和证据，只勾状态，不改任务定义。
- **脚本只证结构**。lint 绿不等于可以开工；开工由人放行。

## 变更类型路由

| 类型                         | 入口     | 说明                                                |
| ---------------------------- | -------- | --------------------------------------------------- |
| 新功能                       | S0       | 完整五步                                            |
| 行为变更 / 修缺陷 / 契约变更 | S1       | 01 必走；02 按需                                    |
| 重构                         | S2       | 外部行为不变时 01 可省；02 必须写“行为不变”的证据 |
| 文案 / 不改外部行为的小改    | 不走 SDD | 直接改                                              |

入口可以选，判断不能省。判不准按上游处理：多走一步是浪费，漏走一步是失控。

## 术语

| 词     | 含义（拥有者）                                     |
| ------ | -------------------------------------------------- |
| 契约   | 长期规则（00）或跨边界接口：外部在 01，内部在 02   |
| 规格   | 可观察行为：谁、什么场景、什么结果；不写步骤（01） |
| 方案   | 构造决策：模块、依赖、数据、顺序、失败处理（02）   |
| 任务卡 | 一次可交付的工作单元及其判据（03）                 |
| 证据   | 证明任务卡完成的可复核输出（03/04）                |
| 放行   | 人确认可以进入下一阶段                             |
| 阻塞   | 上游未定，禁止下游继续                             |

## 断点与维护

新会话只凭 `SDD/` 文件恢复，不靠聊天记忆。文档职责见 `references/doc-set.md`，检查见 `references/checks.md`，恢复与缺件见 `references/resume.md`。

- 入口 ≤ 8 KB；角色卡 ≤ 3 KB；reference ≤ 5 KB；流程 ≤ 5 KB。
- 改模板或脚本后：跑 `examples/todo-cli` 四道检查 + `scripts/check_skill.py` + `scripts/check_loadsets.py .`。
