# 规范驱动开发

## 这是什么

一个受流程和文档约束的角色扮演包：四张角色卡、五份文档、一条四步流程。

角色卡定义的不只是写权限，还有**决策权**：每个角色只能在自己的职责内做决定。越过决策权就是越界，即使文件没写错。

## 治理（项目级，不占迭代）

`00-contract.md` 由人在项目初始化时写一次，定义全局约束：技术栈、依赖政策、目录边界、AI 开发红线。所有角色默认遵守；它不属于某次需求，不在 01 里逐条引用。

## 四步

流程权威见 `workflows/main-flow.md`。

| 步骤 | 角色          | 产出            | 结束         |
| ---- | ------------- | --------------- | ------------ |
| 01   | 01 产品经理   | `01-spec.md`  | 写完即结束   |
| 02   | 02 技术总监   | `02-plan*.md` | 写完即结束   |
| 03   | 03 任务负责人 | `03-tasks.md` | 写完即结束   |
| 执行 | 执行者        | 代码 + 03 证据  | 人按 01 验收 |

## 四张角色卡

| 卡                          | 角色       | 决策权                     | 交接物          |
| --------------------------- | ---------- | -------------------------- | --------------- |
| `roles/01-pm.md`          | 产品经理   | 做什么、不做什么、验收标准 | `01-spec.md`  |
| `roles/02-architect.md`   | 技术总监   | 技术路线、模块边界、接口   | `02-plan*.md` |
| `roles/03-owner.md`       | 任务负责人 | 拆成哪些任务、顺序、批次   | `03-tasks.md` |
| `roles/04-implementer.md` | 执行者     | 任务卡内的实现细节         | 代码 + 证据     |

角色由人挑选，AI 不自己切换角色。

## 角色调用头

每次开工先写回执，作为本次执行单元的边界：

```text
本次角色：<01 / 02 / 03 / 执行>
本次阶段：<01 / 02 / 03 / 执行>
只读：<具体文件清单>
只写：<具体文件清单>
交接：<交给谁、看哪一节>
```

写不出来就停，问一句比猜一次便宜。

## 执行纪律

- **一次只启用一个角色**。写之前先声明角色；声明不了就退回。
- **换角色就换执行单元**。新会话或新 sub-agent，只给上游产物、角色卡和模板；不给上一角色的推理过程。
- **写完即结束**。一个执行单元只做一个阶段，不主动进入下一角色；下一个角色由人启动。
- **不替别人决定**。每个角色有自己的决策权；越过决策权就是越界，即使文件没写错。
- **发现问题回交**。下游发现上游缺口，提交问题包（问题、证据、影响、可选方案），由上游决策；不自行修改上游正文。
- **回上游改正文**。不可行、方案缺口、需求矛盾，回上游改正文，不在下游降级、不私了。
- **单一事实源**。外部契约在 01，内部契约在 02，任务判据在 03；下游引用编号，不复制正文。
- **00 独立于需求**。00 是项目总体约束，所有阶段默认遵守；不在 01 里逐条引用或做冲突裁决。
- **执行者只对任务卡负责**。只写代码、测试和证据，只勾状态，不改任务定义。
- **脚本只证结构**。lint 绿不等于可以开工；开工由人启动。

## 变更类型路由

| 类型                         | 入口     | 说明                                                |
| ---------------------------- | -------- | --------------------------------------------------- |
| 新功能                       | 01       | 完整四步                                            |
| 行为变更 / 修缺陷 / 契约变更 | 01       | 01 必走；02 按需                                    |
| 重构                         | 02       | 外部行为不变时 01 可省；02 必须写“行为不变”的证据 |
| 文案 / 不改外部行为的小改    | 不走 SDD | 直接改                                              |

入口可以选，判断不能省。判不准按上游处理：多走一步是浪费，漏走一步是失控。

## 术语

| 词     | 含义                                               |
| ------ | -------------------------------------------------- |
| 决策权 | 角色能自主决定的范围；越界即失职                   |
| 交接   | 上游把产物、摘要和确认状态交给下游                 |
| 回交   | 下游发现问题退回上游，由原决策角色处理             |
| 契约   | 长期规则（00）或跨边界接口：外部在 01，内部在 02   |
| 规格   | 可观察行为：谁、什么场景、什么结果；不写步骤（01） |
| 方案   | 构造决策：模块、依赖、数据、顺序、失败处理（02）   |
| 任务卡 | 一次可交付的工作单元及其判据（03）                 |
| 证据   | 证明任务卡完成的可复核输出（03）                   |
| 确认   | 人看过产物并启动下一角色                           |
| 阻塞   | 上游未定，禁止下游继续                             |

## 断点与维护

新会话只凭 `SDD/` 文件恢复，不靠聊天记忆。文档职责见 `references/doc-set.md`，检查见 `references/checks.md`，恢复与缺件见 `references/resume.md`。

- 入口 ≤ 8 KB；角色卡 ≤ 3 KB；reference ≤ 5 KB；流程 ≤ 5 KB。
- 改模板或脚本后：跑 `examples/todo-cli` 四道检查 + `scripts/check_skill.py` + `scripts/check_loadsets.py .`。
