# 领域适配：外部契约、验证环境与证据

> 核心规则领域无关。本文件只回答三个问题：这个领域里什么算“用户可观察行为”、在哪里验证、什么算证据。
> 模板里的字段是提示，不是必填项；与领域无关的字段留空或删掉，不要硬填。

## 怎么选

- 以**这次变更的主要外部契约**为准，不要按公司行业选。外部契约写进 `01-spec.md` 的「外部契约」节。
- 一次变更跨多个领域（如 Web + API + 数据库）时，分别写清各端的契约和验证环境。
- 不确定时先用“后端/服务”或“CLI/库/SDK”的通用行，再按实际补充。

## 领域对照

| 领域 | 外部可观察契约 | 验证环境 | 常见风险 | 典型证据 |
| --- | --- | --- | --- | --- |
| Web / 前端 | 页面行为、交互、可访问性、浏览器兼容、加载与错误状态 | 目标浏览器/设备矩阵、真实网络条件 | 可访问性、兼容性、隐私、XSS、性能 | 浏览器/设备测试、截图或录屏、Lighthouse/axe、E2E |
| 移动端 | 安装/升级、权限、离线、推送、商店审核、系统版本兼容 | 真机/模拟器矩阵、目标 OS 版本 | 权限、崩溃、电量/流量、商店政策 | 真机测试、崩溃率、商店预审、升级/回滚验证 |
| 后端 / 服务 | API、状态码、错误码、数据一致性、SLO、限流、鉴权 | 生产等价环境、预发/灰度、依赖沙箱 | 数据迁移、并发、超时、幂等、安全、回滚 | 契约测试、集成/E2E、压测、监控与告警、回滚演练 |
| CLI / 库 / SDK | 命令/参数、退出码、stdout/stderr、公开 API、语义化版本、兼容性 | 支持的 OS/运行时/依赖版本矩阵 | 破坏性变更、依赖冲突、平台差异 | 版本矩阵 CI、契约测试、示例工程、changelog |
| 嵌入式 / 设备 | 设备行为、时序、功耗、通信协议、故障恢复、升级 | 目标板/工装/台架、真实外设与电源条件 | 资源竞争、中断时序、硬件差异、现场升级 | 台架/现场测试、逻辑分析仪、长时间稳定性、升级回滚 |
| 数据 / ML | 数据 schema、口径、质量、模型指标、延迟、可解释性、漂移 | 生产等价数据、评测集、离线/在线实验 | 数据泄漏、偏差、漂移、隐私、不可复现 | 数据质量检查、评测报告、A/B、监控、模型卡 |

## 三个短示例

### 示例 1：Web API

- `01-spec.md`（外部契约节）：`POST /orders` 成功后返回 `201` 和订单号；重复提交返回 `409`；未认证返回 `401`；P95 延迟 < 300ms。
- `02-plan.md`：订单表结构、幂等键、数据库索引、缓存策略、迁移与回滚。
- 验证：契约测试 + 集成测试 + 预发环境压测 + 灰度期间监控 4xx/5xx 与 P95。

### 示例 2：CLI / 库

- `01-spec.md`（外部契约节）：`mytool export --format json` 输出 JSON 到 stdout；失败时退出码非 0 且 stderr 有可读错误；兼容 Python 3.10+。
- `02-plan.md`：参数解析、序列化实现、依赖选择、版本兼容策略。
- 验证：支持版本矩阵 CI、快照测试、退出码/stdio 契约测试、安装包冒烟测试。

### 示例 3：嵌入式设备

- `01-spec.md`：按键长按 2 秒进入配网模式；配网失败 30 秒后回到待机；升级失败自动回滚到上一版本。
- `01-spec.md`（外部契约节）：对外通信协议、升级/回滚承诺（如果外部消费者依赖）。
- `02-plan.md`：GPIO/定时器分配、状态机、通信协议、Flash 分区、看门狗策略。
- 验证：目标板 + 真实外设 + 电源循环 + 长时间稳定性 + 升级/回滚台架测试。

## 契约放哪里

| 契约 | 放哪里 |
| --- | --- |
| 公开 API / CLI / SDK / 对外协议 / 数据 schema / SLO | `01-spec.md` 的「外部契约」节 |
| 同一产品内部的模块/服务接口 | `02-plan-contracts.md` |
| 数据库表 / 索引 / 缓存 key / 内部算法 | `02-plan.md` |

同一个 API，如果只服务本产品自己的前端、不对外承诺，按内部契约放 `02-plan-contracts.md`；如果外部团队、客户或下游系统依赖，放 `01-spec.md` 的「外部契约」节。

## 领域相关的“实现细节”

同一个东西在不同领域可能属于契约，也可能属于实现：

- Web API 的 `POST /orders`、`201`、`409` 是外部契约，应进 `01-spec.md` 的「外部契约」节。
- 订单表的索引、缓存 key、内部服务拆分是内部实现，应进 `02-plan.md`。
- 嵌入式的 GPIO 引脚号通常是内部实现；但如果客户文档把引脚定义作为交付契约，它就应进 `01-spec.md` 的「外部契约」节。

判断标准不是“是不是技术名词”，而是：**外部消费者是否依赖它、能否据此判断做没做到。**

如果产品没有外部消费者，外部契约节写“无外部契约”或直接省略。
