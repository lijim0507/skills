# 机器检查与人工检查

## 机器检查

```bash
python scripts/check_spec.py  <SDD>/01-spec.md
python scripts/check_plan.py  <SDD>
python scripts/check_tasks.py <SDD>/03-tasks.md
python scripts/check_chain.py <SDD>
python scripts/check_skill.py <技能目录>
python scripts/check_loadsets.py <技能目录>
```

## 输出怎么读

- 「结构检查通过 · 语义未验证」= 只证明章节、编号、链条、字段齐全
- 不覆盖：需求可验收性、方案可行性、任务可执行性、模板语义、角色边界
- 脚本绿 ≠ 可以开工；开工由人启动
- 装载集在预算内只证明读的文件没超预算，不证明读得对、读得全

## 人工检查（确认前）

- **01**：每条 FR 有来源、依据、可观察验收；外部契约有 ID、版本、验证方式；范围外写清
- **02**：每条 FR 有可行 / 有条件 / 不可行结论；依赖无环；验证命令可执行；代价已说明
- **03**：每条 FR / EC / 风险有任务覆盖；任务卡自足；没有 `blocked` 未解
- **执行**：DoD 与验收判据满足；证据位置可复跑；没有未登记的偏差

## 交接检查

- 产物末节有「交接给下一角色」，写的是判断，不是正文摘要
- 文档头状态为 `已确认`
- 下游没有替上游改正文；发现缺口有回交记录

## 写之前问四句

1. 我写了不属于我的文档吗？
2. 我做了不属于我的决定吗？
3. 我读了不该读的内容吗？
4. 我把上游缺口在下游私了吗？

任何一句“是”，停，按角色卡的退回规则处理。

## 模板符合度

脚本不检查模板符合度。确认前人工对照 `templates/` 检查：

- 章节顺序是否与模板一致
- 必填字段是否齐全
- 版本 / 状态是否写在文档头

## 回归

改技能后跑 `examples/todo-cli` 四道检查 + `check_skill.py` + `check_loadsets.py` + 空话规格探针（必须失败）。
