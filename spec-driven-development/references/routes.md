# 变更类型路由

不是所有改动都走完整 S0–S9。先判类型，再选入口；门不能省，角色边界不能省。

| 类型 | 起点 | 必走 | 可省 | 产物 |
| --- | --- | --- | --- | --- |
| 新功能 | S0 | S0–S9 | 无 | 00 / 01 / 02 / 03 / 04 |
| 行为变更 | S1 | S1–S9 | 00、02 子件可轻量 | 01 / 02 / 03 / 04 |
| 修缺陷 | S1 | S1、S3、S5、S7、S8、S9 | 00、02 子件、部分门简报 | 01 / 02 / 03 / 04 |
| 重构 | S3 | S3–S9 | 01（外部行为不变时） | 02 / 03 / 04 |
| 契约变更 | S1 | S1–S9 | 00、02 子件按需 | 01 / 02 / 03 / 04 |
| 小改 / 文案 | — | 不走 SDD | 全部 | 无 |

## 入口判据

- **新功能**：有新的消费者、场景或能力，需要新的 P / US / FR。
- **行为变更**：已有功能的结果、规则、边界变了；即使代码很小，也要回 01 改验收。
- **修缺陷**：现有行为与 01 的验收不一致；01 写“错在哪”，02 写根因，03 只拆修复。
- **重构**：外部行为不变；01 可省，但 02 必须写“行为不变”的证据，03 必须有回归任务。
- **契约变更**：外部消费者依赖的接口 / 格式 / 协议变了；先回 01，再走 02/03。

## 轻量模式

小项目可以只保留 01 / 02 / 03；00 并入 README 的“项目宪法”节；04 只写验收记录；02 子件并入 02-plan 对应节。

轻量的是文档量，不是判断量：门不能省，角色边界不能省，签字不能代签。
