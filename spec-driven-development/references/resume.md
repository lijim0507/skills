# 断点恢复

新会话只凭 `SDD/` 文件恢复，不靠聊天记忆。

## 开工前检查

1. 看 `SDD/` 文件清单，确认缺件（00 / 01 / 02 / 03）。
2. 01 开工前跑 `git status --porcelain`：`SDD/` 有未提交改动就停，先提交或明确确认覆盖。
3. AI 读对应角色卡与模板，写角色调用头；用户只选角色。
4. 读上游产物的最新版本，不读聊天记录。
5. 调用头写不出来，退回上游；不猜补。

## 覆盖与 git

文档路径固定（`SDD/00-contract.md`、`01-spec.md`、`02-plan*.md`、`03-tasks.md`），每轮覆盖。历史只在 git 里：覆盖前必须已经提交，否则上一轮的任务勾选和证据永久丢失。

## 未决项

- 需求不确定标 `[NEEDS CLARIFICATION]`，不猜着写。
- 方案或任务与 00 冲突标 `[CONFLICT]`，回人裁决，不自己豁免。
- 执行不确定标 `blocked`，写明卡在哪、等谁。
- 没定的不进正文，定了再改，改了就重新放行。
