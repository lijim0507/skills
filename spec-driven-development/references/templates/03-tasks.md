# 03 · 任务文档（tasks.md）

> 任务状态：`[ ]` 未完成 ｜ `[x]` 已完成 ｜ `[~]` 已作废（内容划删除线，理由见对应变更轮）
> **写入方**：任务与变更轮段由流程维护；「analyze 交叉检查」一节由 `analyze` 写（它的唯一写权限）；`converge` 只追加 Convergence 段的任务。

## 任务格式（强制）

```text
- [状态] T0xx [P?] [US?] 描述 | 涉及文件 | plan 落点 / FR 编号
```

- `[P]` —— 可并行（与同阶段其它 `[P]` 任务无依赖）
- `[US?]` —— 归属哪个用户故事
- 每条任务必须带 **plan 落点或 FR 编号**，否则 `analyze` 会报追溯缺失
- 任务行必须以 `- [ ]` / `- [x]` / `- [~]` 开头，且 `T\d+` 任务号紧跟状态（不要划进删除线、不要用其它项目符号）——校验器只认这一种写法，格式不符的任务会被静默漏计

## 变更轮段（首次变更时新建）

> 首次变更时，把下面的示例复制出来、**去掉围栏**、用真实内容替换；示例本身不要留用（校验器会忽略围栏内的内容，也会把围栏外的示例当成真受理单）。

```markdown
## 变更轮（<日期> r2：<一句话摘要>）

> - **落点**：<宪法 / spec / 澄清 / plan / tasks / 仅实现>（最高处）｜同时触及 <…>
> - **验收场景**：有变化 ｜ <哪条场景、怎么变的> ／ 无变化
> - **重走范围**：<…>
> - **门 1**：待审 ｜ 裁决人：<…> ｜ 日期：<…>   （重走范围里经过的门，各写一条；批准后改成 approve）
> - **门 2**：待审 ｜ 裁决人：<…> ｜ 日期：<…>
> - **判定依据**：<…>
> - **处置记录**：见 `04-converge.md` 变更轮

**本轮作废：**
- T0xx（<原描述要点>）→ 被 T0yy 取代：<理由>

- [ ] T0xx <描述> | <文件> | FR-xxx（r2）
```

> 受理单写完后跑 `check_intake.py`（五栏自洽）与 `check_gate.py`（门结论必须有人批准）；有 git 时再跑 `check_landing.py`（**提交前跑，并用变更前的 ref 作基线**）。**受理单不要放进代码围栏**——围栏内的内容校验器看不见。

> 落点写 `澄清` 时（只改 spec 措辞、验收场景不变）：验收场景必须是「无变化」，重走范围是 `门 1 → analyze`。
