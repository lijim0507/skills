# 文档职责

| 文件 | 写什么 | 不写什么 | 作者 |
| --- | --- | --- | --- |
| 00-constitution.md | 可判定、有编号、注明出处的原则 | 具体实现值 | 人 |
| 01-spec.md | 产品定位、用户故事、FR、外部契约、门 1、交接 | 内部实现选择 | 产品经理 |
| 02-plan.md | 可行性、模块划分、决策、风险、验证、门 2 | 需求与外部契约 | 技术总监 |
| 02-plan-research.md | 每个决策的依据与被否决方案 | 需求 | 技术总监 |
| 02-plan-data-model.md | 实体、字段、状态迁移、归属与写权限 | 模块职责 | 技术总监 |
| 02-plan-contracts.md | 模块清单、依赖方向、模块间契约 | 对外契约 | 技术总监 |
| 03-tasks.md | 批次、任务、任务卡、覆盖映射、检查 | 架构论证 | 任务负责人 |
| 04-converge.md | 收敛结论、验收记录 | 新需求 | 验收人 |

## 归属规则

- 判断一段内容归谁，不看它有没有技术词，看它是谁的决定：对外承诺归 01，实现方式归 02，怎么拆 / 谁做 / 按什么顺序归 03
- 每份文档只有一个作者角色；下游只读上游，不改上游
- 同一事实只写一处：外部契约在 01，内部契约在 02-contracts，任务判据在 03

## 交接摘要

每份文档末尾写「交接给下一角色」，只写 diff 里看不出来的判断：边界、取舍、待确认项。
