# 门禁、简报与签字

## 门简报（每个门先给这一页）

- **要你拍板的决定**：3–5 条，按影响排序
- **代价 / 风险**：工期、成本、运行开销、不可逆点
- **未决项**：是否阻塞，阻塞谁
- **建议**：approve / reject / 退回哪一层

完整清单是附录，不要求裁决人逐条勾。裁决人只看简报和产物做决定。

## 门 1（01 之后）

- [ ] 产品定位完整：消费者、场景、问题、价值
- [ ] 每个主要 / 次要 P 至少一个 US
- [ ] 每个 US 至少指向一个 FR
- [ ] 每条 FR 有来源、依据、可观察验收
- [ ] 每条 FR 通过替换测试：换一种实现仍成立
- [ ] 外部契约有 ID、消费者、版本、验证方式
- [ ] 范围外写清“这轮不做什么”
- [ ] 未决项标明是否阻塞门 1
- [ ] 没有部署形态、模块划分、内部帧格式；步骤化描述已移到 02

## 门 2（02 之后）

- [ ] 需求兑现逐条核对（结论 + 依据，不复述需求）
- [ ] 每条“有条件”都有条件、确认人、关闭点
- [ ] 宪法逐条对答；破例由裁决人批准
- [ ] 模块划分完整：职责、数据、变更原因、写权限
- [ ] 依赖方向明确且无环
- [ ] 每个模块的公开接口只写一次，按模块聚合
- [ ] 关键决策有依据、备选、否决理由、状态
- [ ] 风险、回滚、交付策略写清
- [ ] 验证手段可执行
- [ ] 代价已说明并被产品接受（接受人 / 日期 / 结论）

## 验收（S9）

- [ ] 每条 FR 在目标环境跑过
- [ ] 外部契约验证过
- [ ] 证据位置可复跑
- [ ] 未通过项有回退位置
- [ ] 验收文档版本已记录

## 角色边界检查（每个门）

1. 我写了不属于我的文档吗？
2. 我做了不属于我的决定吗？
3. 我读了不该读的内容吗？
4. 我把上游缺口在下游私了吗？

## 签字

```text
approve ｜ 裁决人：<名字> ｜ 日期：YYYY-MM-DD ｜ 版本：rN
```

未表态写 `待审`。正文一改，旧签字作废，回到 `待审`。

## 写权限

- 门结论只由裁决人写，agent 不代签。
- 评审者只写评审记录，不写正文。
- 02 / 03 / 04 接手先复述；复述不出来就退回。
- `analyze` 只写自己那一节。
- `converge` 只追加任务，不改正文。
- 上游未定的事项回上游，不在下游私了。

## 停机动作

- 到门即停，不在同一步继续写下游或代码。
- 未批准不得开工；“你看着办”仍按待审处理。
