# 三道关卡：门 1、门 2、验收

## 对照

| | 门 1 | 门 2 | 验收 |
| --- | --- | --- | --- |
| 谁判 | 人（产品视角） | 人（技术视角） | 人 |
| 何时 | `01-spec.md` 写完（含外部契约） | `02-plan*.md` 写完（含内部契约） | 实现 + converge 之后 |
| 审什么 | 每条需求能不能判做没做到；外部契约是否可验证 | 方案可行吗；内部契约是否自洽；逐条对答宪法 | 按 `01-spec.md` 的验收场景和外部契约实测 |
| 通过 | `approve ｜ 裁决人：… ｜ 日期：…` | 同左 | 结论落 `04-converge.md` |
| 不通过 | reject → 回 `01-spec.md` 修，重跑门 1 | reject → 回 `02-plan*.md` 修，重跑门 2 | 不通过 → 回上游 |

## 门是阻塞点

写完 spec / plan **必须停下**，把文档交给裁决人审批，拿到明确 approve 才能往下走。

**不得自行填写 approve**，也不得在未获批时继续往下走。**不要在同一步里**写完 spec 就顺手改 plan 或改代码。

### 门的四步

- **停**：写完 `01-spec`（或 `02-plan`）后，不在同一步里继续改下游文档或代码
- **请**：明确说出「请审批门 N：approve / reject」，然后**结束本轮**等回话
- **记**：只有回话里出现明确批准（「批准」「approve」「可以」）时才写结论行；**裁决人写用户，不写你自己**。用户没表态或只说「你看着办」→ 保持 `待审`
- **驳**：reject 或提出修改 → 退回该门上游修，修完重跑该门，**不得带病继续**

**不要另开一个「请确认落点」的停顿**：落点决定重走范围，而重走范围的第一站就是一道门。

## 变更时只审变动部分

**没动过的部分沿用上次的结论，不重审。**

所以「门 2 复审维持 approve」不是橡皮图章，它的准确含义是：没变的部分保持原结论，变了的部分重新审。门只有一道，变的是**审查范围随 diff 收缩**。

## 门 1 的清单

清单是**需求与外部契约的单元测试**——不测代码，测需求写得好不好、契约能不能被验证。它在 `01-spec.md` 的门 1 小节里，**由裁决人勾**：`[x]` 表示「这条需求/契约质量达标」，**不代表实现工作已完成**。

检查项：

- 每条 FR / SC 有唯一编号，且都能判做没做到（有可观察的判定条件）
- 没有 `[NEEDS CLARIFICATION]` 残留
- 边界与异常情况都列了
- `01-spec.md` 里没有内部实现选择（框架、模块划分、内部标识、私有参数等）
- 每条 FR 都挂在某个用户故事下
- 如果有外部消费者，`01-spec.md` 的「外部契约」节已写清；如果没有，已明确写“无外部契约”
- 每条外部契约都能被外部消费者验证，且关联到用户故事、FR 或 SC

## 门 2 的清单

- 宪法逐条对答过（符合，或违反 + 理由 + 复杂度跟踪里的破例说明）
- 每个技术选择都能回答「它服务哪条需求」
- 验证手段可执行（在什么环境、用什么数据/工具、跑什么命令、拿什么判通过）
- Phase 0 / Phase 1 子件与 `02-plan.md` 自洽
- 内部方案兑现 `01-spec.md` 的外部契约，不重复定义
- `02-plan-contracts.md` 只写产品边界内部的契约

## 脚本抓不住署名

`scripts/check_spec.py` 能拦「忘了批」——`待审`、`reject`、占位符（`<…>`）都过不去。

**它抓不出「谁签的字」**：裁决人一栏填的是不是真人，只有人自己守得住。所以规则写成「未获用户明确批准时一律填 `待审`」，而不是假装脚本能识破自批。

## 单人时的门是什么

门 1 和门 2 是同一个人签，这在个人项目里是常态。这时两道门的真实作用是**强制一个停下来重读的时机**——它是**冷却期**，不是独立评审。

**它拦得住「没看就往下走」，拦不住「判断错了」。** 想要真正的独立意见，用独立上下文的 agent 扮演评审角色（见 `references/roles.md`），但 `approve` 仍由人签。

## 验收（S8）

`converge` 只证「代码没背叛文档」，证不了「在目标环境里真的做到了」。实现完成后由人按 `01-spec.md` 的验收场景和外部契约在**真实运行环境**中跑一遍，结论落 `04-converge.md`。**这一步没有替代品。**
