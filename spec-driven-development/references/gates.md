# 门禁与写权限

## 门 1（01 之后）

- [ ] 产品定位完整：消费者、场景、问题、价值
- [ ] 每个主要 / 次要 P 至少一个 US
- [ ] 每个 US 至少指向一个 FR
- [ ] 每条 FR 有可观察验收
- [ ] 每个 P 与每条 FR 有依据，不是凭空设定
- [ ] 没有内部实现选择，外部契约可验证
- [ ] 没有部署形态、模块划分、内部帧格式

结论格式：`approve ｜ 裁决人：<用户> ｜ 日期：YYYY-MM-DD ｜ 版本：rN`；未表态写 `待审`；正文一改，旧签字作废，回到 `待审`。

## 门 2（02 之后）

- [ ] 需求可行性逐条核对，不可行项已回 01
- [ ] 宪法逐条对答
- [ ] 模块划分完整：职责、读写的表、写权限
- [ ] 依赖方向明确且无环
- [ ] 关键决策有备选与否决理由
- [ ] 风险、回滚、交付策略写清
- [ ] 验证手段可执行
- [ ] 代价已说明并被产品接受（工期 / 资源 / 成本 / 运行开销）

## 写权限

- 门结论只由裁决人写，agent 不代签
- 签字绑定正文版本；正文一改，旧签字作废
- 评审者只拿产物与清单，不参加写作；结论写「查了哪些项、发现几条、在哪」
- 02 / 03 接手先复述；复述不出来就退回，不靠猜补
- `analyze` 只写自己那一节
- `converge` 只追加任务，不改正文
- 上游未定的事项回上游，不在下游私了

## 停机动作

- 到门即停，不在同一步继续写下游或代码
- 未批准不得开工；「你看着办」仍按待审处理
