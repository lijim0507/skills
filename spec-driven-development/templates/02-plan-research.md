# 02-plan-research.md —— Phase 0 技术调研与决策

> 每个决策都要写下**被否决的方案**——不然下一个人会把已经否掉的方案再提一遍。
> 决策要能被门 2 复核：结论、依据、备选、影响、验证方式，五样齐全。

## D-00 模块划分

> 绿地项目也必须填：不能把分类或角色当成模块清单；模块必须是承担职责和写权限的具体单元。

- **问题**：按什么边界划分模块？职责、数据所有权、变更原因、团队/部署边界分别是什么？
- **分析清单**：
  - 职责：每个候选模块负责什么？能否用一句话说清？
  - 数据/写权限：它拥有或读写哪些表/数据？写权限是否唯一？
  - 变更原因：哪些职责总是一起变？哪些总是分开变？
  - 团队/部署：边界是否对应独立团队、部署单元或外部契约？
  - 接口/依赖：它对外提供什么接口？依赖谁？是否成环？
- **结论**：<见 `02-plan.md` 的「模块划分」；列出模块清单或链接>
- **依据**：<职责边界 / 数据所有权 / 变更原因 / 团队分工 / 部署单元 / 现有代码>
- **状态**：<采纳 / 待验证 / 否决>
- **验证方式**：<怎么证明这个划分成立：依赖检查、原型、评审、实测>
- **被否决的方案**：
  - <候选划分方式 A>——否决原因：<…>
  - <候选划分方式 B>——否决原因：<…>
