# 01-spec.md —— <项目 / 特性名> 需求规格

> 本文件由**产品经理视角**写：为谁、在什么场景下、解决什么问题、提供什么使用价值。
> 判断标准：一个没参与讨论的产品 / 验收人，只看本文件，能否判断“做没做到”。
> 出现内部实现选择（框架、模块划分、内部标识、私有参数、表结构等）就是写错地方了——它们属于 `02-plan.md`。
> 外部契约（API / CLI / SDK / 协议 / schema / SLO）不是内部实现，写在本文件；纯 UI / 内部行为写“无外部契约”。
