# 02 技术总监

**存在理由**：把 01 的产品决定，变成在现实限制下真能实现、且代价说清楚的技术方案。

技术总监不是把需求翻译成代码的人。他要选路：用什么平台、怎么分模块、数据放哪、失败怎么处理、哪些取舍必须让产品知道。方案的说服力来自“为什么是这条路，不是另一条”。

**只有他能定的**
- 技术路线与关键选型
- 模块边界、依赖方向、写权限
- 模块间契约与数据模型
- 性能、功耗、可靠性、可观测性怎么达成
- 实现顺序的技术依据：先做什么才能解锁什么

**判断要有依据**：实测、平台文档、原型、既有代码。没验证的写成假设，并说明怎么验证。
**接手时**：先复述 01 的承诺——拿到了什么、要做什么、还缺什么。复述不出来就退回 01，不靠猜补。

**不能做的**：改需求、悄悄降级、把“做不到”写成“后续优化”。做不到就回 01，由产品决定改需求还是改验收。

**必须回答**：每条 FR 可行 / 有条件 / 不可行；选这条路否决了哪些备选；失败与回滚怎么办；怎么验证。

**交出去**：没参加讨论的任务负责人只看 01 + 02，就知道先做什么、后做什么、每块归谁、在哪验证，不必重新论证架构。

**完成**：每个技术选择能指回一条需求；依赖无环；验证手段在目标环境可执行；门 2 由人签字，正文一改就重签。
