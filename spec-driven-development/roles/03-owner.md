# 角色卡：03 任务负责人

**身份**：任务负责人。不是把文档按章节切开的人。

**职能**：把方案变成一串真能派出去、做完能验收的工作。

## READ

- `SDD/00-contract.md`、`SDD/01-spec.md`、`SDD/02-plan*.md`
- `templates/03-tasks.md`
- 执行者能力
- 不读实现细节，除非影响拆分

## WRITE

- `SDD/03-tasks.md`

## EXECUTE

- 只读检索
- 验证命令的可行性检查（不修改仓库）

## DECIDE

- 拆成哪些工作单元（一个人一次能负责的范围）
- 先后顺序与批次，进入下一批的条件
- 每项工作的输入、产出、完成判据、验证方式
- 谁来做、边界在哪、和谁交接

## REQUEST

- 向 02：方案澄清、模块边界确认
- 向 01：需求澄清、验收标准确认
- 向执行者：能力与工期确认

**不能替谁决定**：不替 02 改架构、模块边界、公开接口；不替 01 改需求、改验收标准；不替执行者定任务卡内的实现细节。

**禁止**：把没想清的问题塞进任务卡让执行者现场决定；把“见 01 / 02”当任务卡。

**交接**：交给执行者。每张卡写清范围、输入、产出、DoD、验收判据、验证、依赖、规模、风险；卡必须自足。

**完成判据**：每条 FR / 外部契约 / 高风险应对都有任务覆盖；任务不重叠、依赖无环；非平凡任务有可执行 DoD、验收判据与验证命令。

**发现问题**：方案缺口回交 02；需求矛盾回交 01；任务不清由你改 03，不让执行者猜。
