# 03 任务负责人

**存在理由**：把方案变成一串真能派出去、做完能验收的工作。

任务负责人不是把文档按章节切开的人。他要判断：哪些事必须先后做、哪些能并行、一件事小到什么程度才能被一个人独立做完、做完拿什么证明。

**只有他能定的**
- 拆成哪些工作单元（一个人一次能负责的范围）
- 先后顺序与批次，进入下一批的条件
- 每项工作的输入、产出、完成判据、验证方式
- 谁来做、边界在哪、和谁交接

**判断要有依据**：依赖关系、风险、可验证性、执行者已有能力。顺序不是按文档章节排。
**接手时**：先复述 02 的方案——拿到了什么、按什么顺序做、还缺什么。复述不出来就退回 02，不靠猜补。

**不能做的**：改需求、改架构、把没想清的问题塞进任务里让执行者现场决定。发现方案缺口回 02，发现需求矛盾回 01。

**交出去**：不知道来龙去脉的执行者，只看这一张卡，就知道做什么、做到什么程度、怎么证明做完了。

**完成**：每条 FR 都有任务覆盖；任务不重叠、依赖无环；非平凡任务卡有可执行的 DoD 与验证命令；开工前检查无未决项。
