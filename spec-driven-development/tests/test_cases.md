# 测试用例

## check_spec.py

### 用例 1：完整规格通过
- 输入：含「用户场景与测试 / 需求 / 成功标准」，用户故事带验收场景，有 SC-xxx
- 期望：输出 `规格校验通过`，退出码 0

### 用例 2：缺章节
- 输入：缺「用户场景与测试」「成功标准」的 spec
- 期望：逐条报 `错误：缺少必需章节「…」`，退出码 1

### 用例 3：用户故事缺验收场景
- 输入：有 2 个用户故事但只有 1 个 `**验收场景**`
- 期望：报错提示验收场景是落点判定的锚点，退出码 1

### 用例 4：spec 里混进实现细节
- 输入：正文出现 `GPIO21`、`uint8_t`
- 期望：报 `警告：spec 里出现实现细节`，退出码 0（警告不阻断）

## check_intake.py

### 用例 5：受理单自洽
- 输入：变更轮受理单，落点 `spec`，重走范围含 `门 1`
- 期望：输出 `受理单校验通过`，退出码 0

### 用例 6：落点与重走范围矛盾
- 输入：落点 `spec`，重走范围只写 `门 2 → tasks → implement`
- 期望：报 `落点为 spec，重走范围却未包含 门 1`，退出码 1

### 用例 7：受理单缺栏
- 输入：受理单只有「落点」，没有「重走范围」「判定依据」
- 期望：报缺少栏位，退出码 1

### 用例 8：受理单把「同时触及」单开一栏
- 输入：受理单在落点行之外另起一行 `> - **同时触及**：plan（…）`
- 期望：报 `「同时触及」应并入落点行`，退出码 1

### 用例 9：无变更轮
- 输入：首轮建档的 tasks.md（没有变更轮小节）
- 期望：只输出提示，退出码 0（首轮正常）

## check_tasks.py

### 用例 10：作废任务格式正确
- 输入：`- [~] T026 ~~原描述~~ | FR-040/041` 且下一行是 `⤷ r2 作废：…`
- 期望：输出任务统计（未完成 1 ｜ 已完成 0 ｜ 已作废 1），退出码 0

### 用例 11：作废任务缺删除线
- 输入：`- [~] T099 某任务 | FR-001`，无删除线、无 ⤷ 行
- 期望：报两条错误（无删除线、缺 ⤷ 说明），退出码 1

### 用例 12：任务缺追溯
- 输入：任务既无 plan 落点也无 FR 编号
- 期望：报 `警告：…没有 plan 落点或 FR 编号`，退出码 0（警告不阻断）
