# Changelog

## 2.2.0 - 2026-10-09

**修可用性**：规则本身没推翻，补的是「agent 真按它执行时会卡在哪」。

### Added

- **落点新增「澄清」**：改的只是 `01-spec.md` 的措辞、验收场景一个字不变 → 重走 `门 1 → analyze`。此前这种改动会连着答四个「不」、被判成「仅实现」塞进 `converge`（`SKILL.md` 落点表、`check_intake.py`、`references/landing.md`、`03-tasks.md` 模板四处同步）
- **「前提假设」节与 `<!-- impl-ok -->` 标记豁免实现细节检查**：`doc-set.md` 允许外部给定的硬约束写进 spec，但 `check_spec.py` 会把它们报成警告、门 1 清单第 4 项因此无法合法勾选——现在这两处不报
- 规模下限与「建项前先问用户」：没有文档集时先问要不要建，用户不建就退出；单个文件、不改外部可观察行为的小改不再触发建项
- 门写成可执行动作（停 / 请 / 记 / 驳），明确「用户口头批准后由 agent 代录、裁决人写用户、未批准一律 `待审`」
- `check_landing.py` 在基线为 `HEAD` 时提醒改用变更前的 ref；`--since` 帮助文本同步

### Fixed

- `check_spec.py` 只数验收场景总数，2 个故事把场景块都写在第一个故事名下会漏过——现在按故事分段校验
- `check_gate.py` 的 `find_verdict` 按词表顺序先匹配 `reject`，结论里提到历史 reject（如「approve（上一轮 reject 已修复）」）会被误判成驳回——现在只看第一个「｜」之前、且取最早出现的判定词
- `README.md` 里 `check_gate.py` 的命令行孤悬在「安装」第 2 条后面，脚本清单里反而漏了它
- 「受理单完整示例只在 `references/landing.md` 出现一次」与 `examples/change-round.md` 的事实不符，改为「字段与格式以该节为准，示例是它的展开」
- `references/quality-mechanisms.md` 复述了 `SKILL.md` 的「两类关卡」表，与「references 只解释、不复述」相抵——改为指向

### Changed

- 「`check_gate.py` 能抓出自批自过」的说法删掉：脚本只拦「待审 / reject / 占位符 / 缺裁决人与日期」，**署名是不是真人查不出来**（`references/quality-mechanisms.md`、`references/rationale.md`、`check_gate.py` 文档串、README 同步）
- `tests/eval.yaml` 版本号跟上 skill（此前停在 2.1.0）；补用例，`tests/test_cases.md` 同步

## 2.1.1 - 2026-10-09

**瘦身**：把「给人读的」和「给 agent 执行的」分开。**规则一条没动**，5 个校验脚本与模板均未改。

### Changed

- 新增 `references/rationale.md`：设计由来、为什么这样划写权限、两次真实事故（原先散在 `SKILL.md`、`drift.md` 与示例里）
- `SKILL.md` 只留 agent 要执行的东西（判据、落点表、重走顺序、两类关卡、写权限与证据、Instructions、Done When）
- 完整状态图移到 `references/quality-mechanisms.md`，`SKILL.md` 只留一行重走顺序
- 受理单完整示例移到 `references/landing.md`（唯一出处），`SKILL.md` 只列字段名
- 真实事故叙事只保留在 `references/rationale.md`，`drift.md` 与示例改为一句引用


## 2.1.0 - 2026-10-09

**整体性整合**：把 2.0.0 里靠事故补丁堆起来的规则，收敛到「一个判据 / 一条链 / 一份证据」上，并补上缺的机械兜底。

### Changed

- **单一事实源**：落点表、重走范围、状态机、写权限表只保留在 `SKILL.md` 的「流程模型（唯一权威）」一节；原先散在 5 处的重复表全部删除，其余文件只解释、不复述
- **统一命名**：只叫「门 1 / 门 2」，去掉 `review-spec` / `review-plan` / 「评审门」等并存写法
- **判据归位**：把「落点判定」「漂移三分类」「范围裁剪」「内容归属」写成同一条判据的四个调用点，不再是四段并列规则
- **关卡模型**：三道「质量机制」重构为**人审门**（阻塞点，人 approve/reject）与**机器守卫**（analyze / converge），并给出写权限与退出证据表
- **门是阻塞点**：明确「写完必须停下等人工 approve，不得自行填写 approve」——原版本只有名词没有动作
- **门批准记录一体化**：门结论的落点统一为两处（首轮在被审文档的门小节、变更轮在受理单），新增 `check_gate.py` 校验「必须 approve + 裁决人 + 日期」——把「不得自批自过」从口号变成机械检查
- **受理单加第五栏**「验收场景」（有变化 / 无变化），让落点声明可被证伪
- **`analyze` 的「只读」改为可判定表述**：不改被检查内容，唯一写权限是 `03-tasks.md` 的「analyze 交叉检查」一节（原文说「从不修改文件」却要求写入这一节，自相矛盾）
- **`checklist` 归位**：它就是 `01-spec.md` 门 1 内的需求质量清单，删掉孤儿引用 `requirements-quality.md`
- **补上宪法的落点**：宪法变更 = Governance 修订 → 门 1 → …；原先主干图提到 Governance 修订，落点表里却没有这一档

### Added

- `scripts/check_landing.py`：把受理单的落点与验收场景声明和 `git diff` 对照——2.0.0 声称「脚本能复核落点判得对不对」，这次真的做了
- `scripts/check_gate.py`：校验门的批准记录。它原先自带一套 `评审门 1` / `裁决人` 的命名与另一份约定，这次并入统一模型：标题兼容 `门 N` 与 `评审门 N`，并补齐围栏感知与轮次标题容错
- 宪法落点、任务号外露校验、代码围栏感知、章节名容错（「功能需求」）、门 1 结论行检查

### Fixed

- 变更轮标题写成 `## r3 变更轮：…` 时被静默跳过（原先只认 `变更轮` 紧跟标题）——现在会识别
- 作废任务把任务号划进删除线时，原先既不报错也不计数（任务凭空消失）——现在报错并计入统计
- 用 `* [ ]` 或缩进写的任务行原先被静默漏计——现在会被统计
- 受理单写 `门1`（无空格）原先误报「未包含 门 1」——现在比较前先归一化空白
- spec 用 `## 功能需求` 原先误报「缺少必需章节」——现在容错
- 模板自身通不过校验器（示例用户故事缺验收场景、示例变更轮被当成真受理单、`T9xx` 被解析成 T9）——现在围栏内的示例一律跳过，模板自身可通过

## 2.0.0 - 2026-10-08

### Changed

- **推翻 1.0.0 的设计**：取消小/中/大分级与五态状态机，改为**落点判定**（改动落在哪份文档就重走多远）
- **拆出 plan 层**：1.0.0 的单一 `spec.md` 违反内容归属判据，现改为 spec（what/why）+ plan（how）+ Phase 0/1 子件
- **补齐漂移三分类**：需求漂移 / 实现漂移 / 放错位置的漂移，取代 1.0.0 的「回退重审」
- **补齐受理单格式**：落点（含同时触及）+ 重走范围 + 判定依据 + 处置记录
- **补齐异常路径**：门 reject 退回上游、converge 发现数必须严格递减、blocked 显式标记
- **补齐范围裁剪**：FR 编号不重用，走门 1
- **补齐起步流程**：绿地建项 / 棕地回溯（偏差进「待办与偏差登记」，逐条确认偏差）
- **去掉 `02-plan-quickstart.md`**：它把「项目级运行说明」与「`01-spec.md` 验收场景的复述」装在一起，且没有任何检查机制消费它

### Added

- 三个校验脚本：`check_spec.py`、`check_intake.py`、`check_tasks.py`
- `references/` 五份规则文档 + 八份文档模板
- `examples/change-round.md`
